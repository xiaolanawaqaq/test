# 微尘 Weichen — TapTap 聚光灯 GameJam 2026 「涌现」候选作品

**没有一颗尘埃，知道星云的形状。** 120–180 颗尘埃遵守三条规则——**趋光**、**结伴**、**生灭**；
你只在场上放**光源**和**毒域**，然后看群体自己组织出
**星云**、**漩涡**、**流动群落**——每一种都是宏观上涌现、微观上没被写死的形态。

自动化模拟 3066/0、UI 89/0；Android 真机、TapPlay、账号上传和真实玩家试玩尚未完成。

## 三类要素（物质 / 能量 / 扰动）

游戏的全部世界由三类要素构成，开场简介就是这三句话：

| 要素 | 定位 | 实际作用 |
|---|---|---|
| **尘埃：物质** | 基础个体，无脑、随波逐流 | 只感知身边的光，与同伴相互牵引；能量充足时分裂，能量耗尽时消散，是构成一切结构的基础 |
| **光源：能量与秩序** | 玩家引导群体的主要工具 | 自带引力，吸引尘埃汇聚并提供能量，让群落生长 |
| **毒域：扰动** | 涌现的催化剂 | 驱散结构、消耗能量、改变流向，为新的秩序腾出空间 |

"病毒"原案里的**扰动与重组**意图由毒域承担；病毒感染 / 吞噬 / 变异属于赛后扩展方向，当前版本不承诺也不宣传。

开场文字（0.1.2 起内置于游戏首屏）：

> **没有一颗尘埃，知道星云的形状。**
>
> 尘埃是物质：只感知身边的光，与同伴相互牵引，能量充足时分裂，能量耗尽时消散。
> 光是能量：吸引尘埃汇聚，让群落生长。
> 毒域是扰动：驱散结构、消耗能量，为新的秩序腾出空间。
>
> 你无法命令任何一颗尘埃，只能改变它们身处的环境。
> 看散落的微尘，如何在聚集与扰动之间，长出星云、漩涡与流动的群落。
>
> **「放下第一束光」**

## 玩法

- 首屏是开场简介；点「放下第一束光」进入观测，90 秒窗口从这一刻起算。
- 每局由种子决定一个观测目标（如“漩涡稳定3秒”），完成后结算有加分。
- 光源 / 毒域放置会被记录；「更多」里的“重放本局”按原时间点重演，逐帧一致。
- 检测到星云 / 漩涡 / 流动群落时，场地会在该结构处画出高亮环并标名。
- 「更多」里的速度按钮可 x1/x2/x4 加速观测；现象判定不受速度影响。
- 每局 90 秒观测窗口，或尘埃全部消散时提前结算。
- 目标 / 倍速 / 重放收在「更多 ▾」里，首屏只围绕尘埃、光和毒。
- 桌面端：左键固定放光源、右键固定放毒域；触屏端：「光源 / 毒域」按钮选择后点场地。
- 光源会吸引尘埃并给能量；能量足的尘埃会分裂。
- 毒域会驱散并耗尽尘埃；毒域铺错会直接把群落打散。
- 顶部实时显示粒子数、剩余干预次数、计时和当前现象标签。
- 结算可一键复制种子、现象、峰值和得分，离线比对。

## 为什么是「涌现」
- 星云：高密度团在引力互相拉扯中自行聚拢，没有"形成星云"指令。
- 漩涡：邻居之间的切向偏置让局部旋转自行稳定，没有"旋转"指令。
- 流动群落：一致的群体速度是局部对齐的副产物，没有"集体行进"指令。
- 玩家的光源 / 毒域只是扰动；图案是尘埃自己长出来的。

## 工程
- Godot 4.6.3，GL Compatibility；无网络、无账号、无第三方素材。
- 纯数据模拟层（`dust_sim.gd`）：固定 30 Hz、确定性整数哈希、
  平行 packed-array 存储、counting-sort 空间网格、O(n) 邻居查询。
- 渲染层（`dust_field.gd`）：纯 `_draw()` 程序化绘制，无图片资源；
  尘埃颜色即能量（暗红→蓝白→金黄色温谱），背景为双色星云。
- 音频层：背景音乐与音效由 `tools/generate_music.py` 程序化合成（无第三方素材）；
  背景乐为 Am–F–C–G 稀疏留白式配乐（64 秒循环，大量安静间隙），
  音乐分层——现象出现时第二层短句琶音浮现，消失时退去。
  所有按钮有轻微点击音（-13 dB，可一键静音）。
- 序列化用量化 JSON，可验证同一种子+同一输入的确定性重现；“同种子重开”会重新开始本种子，不会自动播放旧操作。
- 模拟层测试 3066 断言全通过；UI 测试 89 断言全通过。

## 从源码运行

使用 Godot **4.6.3 stable** 打开仓库根目录的 `project.godot`，等待资源导入完成后按 **F5** 运行主场景。也可以从命令行启动编辑器：

```sh
git clone git@github.com:xiaolanawaqaq/wechen.git weichen
cd weichen
godot --editor --path .
```

运行自动化测试前，先导入资源：

```sh
godot --headless --editor --path . --import
godot --headless --path . --script tests/test_dust_sim.gd
godot --headless --path . --script tests/test_weichen_ui.gd
```

仓库保留 GDScript、场景、工程配置、音频、资源导入设置、测试、开发工具与文档；不包含安装包、二进制图片、Godot 缓存、Android 构建目录、测试截图或签名密钥。音频文件是游戏运行所需资源，旁置的 `.import` 文件还保存背景音乐循环等设置，不应删除。

`export_presets.cfg` 保留 Windows、Linux 和 Android 导出配置。导出时需另行安装对应版本的 Godot 导出模板；Android 还需安装 Android 构建模板、JDK 和 Android SDK，并在本地配置签名；启动器图标字段已清空，如需自定义图标，请在本地放置 PNG 并在导出预设中重新设置。`tools/export_android.py` 的 JDK/SDK 路径是本机配置，换机器时需要调整；签名凭据通过仓库外的 JSON 文件提供，凭据与构建日志均不应提交。
